# Маршрут «Синяя Рука» — веб-приложение

Лёгкая мобильная веб-версия 13-дневного маршрута (22 сентября — 4 октября 2026).
Чистый HTML/CSS/JS, без сборки, без бэкенда — всё, что описано в ТЗ.

## Структура

```
index.html          — единственная HTML-страница (приложение — SPA)
css/style.css        — все стили
js/data.js            — ⭐ ЕДИНСТВЕННЫЙ файл, куда вставлять финальные тексты
js/intro.js           — текст вступительного экрана
js/app.js             — вся логика (время, состояния дней, анимация, карточки, финал)
assets/                — изображения и видео (оптимизированы для мобильного веба)
vercel.json, _redirects — конфиги для деплоя (см. ниже)
```

## Как это работает

- **Три входа, один маршрут.** Режим определяется по URL и один раз запоминается в localStorage браузера:
  - Наблюдение: `/nablyudenie` (или `/observation`, или `?mode=observation`)
  - Путешествие: `/puteshestvie` (или `/journey`, или `?mode=journey`)
  - Погружение: `/pogruzhenie` (или `/immersion`, или `?mode=immersion`)

  Пришлите людям именно ссылку с нужным путём — например `https://ваш-домен/puteshestvie`.
  Контент дня одинаков во всех трёх режимах, отличается только блок «След».

- **Время маршрута** считается по Москве (UTC+3), не зависит от часового пояса телефона пользователя.
  До 22 сентября — экран ожидания. С 22.09 по 04.10 — открыт только текущий день. После 04.10 — у всех финальный экран.

- **Ничего не хранится на сервере.** Всё состояние — это два флага в localStorage браузера:
  просмотрено ли вступление и в какой день пользователь уже входил сегодня (чтобы не повторять карточку
  как «новый вход», но при этом анимация всё равно проигрывается заново при каждом клике по активной точке — как в ТЗ).

- **Тексты дней и практик** — в `js/data.js`, массив `BH_DAYS`. Сейчас там плейсхолдеры
  с пометкой `[PLACEHOLDER]`. Когда придут финальные тексты 13 карт и 26 практик — замените
  строки внутри `seal`, `tone`, `sealShort`, `toneShort`, `connection`, `about`, `practice1.title/text`,
  `practice2.title/text` для каждого дня. Структуру и ключи менять не нужно.

## Проверка на разных датах (без перевода системных часов)

Добавьте к адресу `?debugNow=2026-09-25T10:00:00`, чтобы приложение думало, что сейчас это время
(парсится как московское). Уберите параметр для реального времени. Работает и вместе с режимом:
`/puteshestvie?debugNow=2026-10-05T00:00:00` покажет финальное завершённое состояние.

## Деплой

Это статический сайт — подходит любой статический хостинг (Vercel, Netlify, Cloudflare Pages,
обычный nginx). Важно только одно: **любой путь должен отдавать `index.html`**, чтобы работали
три входные ссылки `/nablyudenie`, `/puteshestvie`, `/pogruzhenie` (это SPA-роутинг на клиенте).

- **Vercel**: конфиг уже есть (`vercel.json`) — просто занести папку в проект и задеплоить.
- **Netlify**: конфиг уже есть (`_redirects`) — то же самое, простое перетаскивание папки
  на app.netlify.com/drop тоже сработает.
- **Свой сервер / nginx**: настроить `try_files $uri /index.html;`.

## Что сознательно не сделано (по ТЗ, раздел 13)

Нет Supabase, нет хранения ответов, нет дневника, нет кодов доступа, нет регистрации,
нет личного кабинета, нет админки, нет архива прошедших дней, нет конструктора маршрутов
и никакой аналитики «на будущее». Рисунок на сцене не зависит от действий пользователя —
только от календарной даты.

## Ограничение автоплея видео на iOS

Финальное видео Day 13 запускается автоматически (без звука, `playsinline`) сразу после
нажатия «Завершить маршрут» — по спецификации это происходит по жесту пользователя, так что
автоплей должен пройти на всех современных мобильных браузерах. На случай, если конкретный
браузер всё же заблокирует автоплей, предусмотрена запасная кнопка «Продолжить».
